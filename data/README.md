# Данные закупочных каталогов

Снимки собраны 6–9 октября 2026 года. В репозитории опубликованы **только Parquet-каталоги** (Git LFS) и этот README; сырые JSON/JSONL, SQLite и прочие рабочие файлы в снимок не входят. Приложение из `search-web/` и секреты не включены.

## Получение

Установите Git LFS перед клонированием:

```bash
git lfs install
git clone https://github.com/dantetemplar/zakupki-reverse.git
cd zakupki-reverse
git lfs pull
```

`*.parquet` — колоночные данные с внутренним сжатием Zstandard. Старые JSON/JSONL-снимки и промежуточные прогоны хранятся только локально вне репозитория.

## Каталоги и источники

### СТЕ: Портал поставщиков Москвы

Источник: [zakupki.mos.ru](https://zakupki.mos.ru/).

- **`ste.parquet` — основной каталог СТЕ:** **300 000** записей, тот же компактный формат, что у `*_from_api.parquet`. Слит из списка Search/QueryIndex и карточек GetSku (одинаковые id, один порядок). Характеристики (~3,1 млн), описание, КПГЗ/категория/ОКПД2; `okpd2_*` из `production.okpd` карточки, иначе из списка/`pp-kpgz`. У 28 id GetSku вернул 403 — для них взяты поля QueryIndex-снимка. Выборка ограничена фильтром `entityState=2`, `skuStateId=61000002` (`extend_ste_list_qi.py`), не полный каталог.
- `ste-categories.parquet`: **14 743** записи дерева категорий СТЕ из Портала поставщиков.
- `pp-kpgz.parquet`: **15 075** записей классификатора продукции/КПГЗ в представлении Портала поставщиков, с иерархией и связями с ОКПД2.
- `Инструменты_from_api.parquet`, `Мебель_from_api.parquet`, `Одежда_from_api.parquet`: по ~100 000 карточек СТЕ из QueryIndex по спискам ID из соответствующих `.xlsx`. Тот же schema, что `ste.parquet`.

Для справочников Портала отдельный полный журнал HTTP-запросов не сохранился. Не следует считать идентификаторы одинаковыми между разными системами.

### КПГЗ и СПГЗ: ЕАИСТ Москвы

- `spgz.parquet`: **83 485** записей СПГЗ, включая связи и характеристики. Источник: [экспорт СПГЗ ЕАИСТ](https://eaist.mos.ru/module/nsiexportservice/api/v1/dicts/spgz). Это представление ЕАИСТ, отдельное от `pp-kpgz.parquet`; совпадение кодов не означает совпадение локальных ID.

### КТРУ: предпочтительный XML → Parquet

- **`ktru-actual.parquet` — основной источник КТРУ:** **20,4 МБ** (Zstandard), **81 461 строка / уникальный код**, **330 542 характеристики**, **1 067 566 значений**, из 82 XML-частей `actual` архива `КТРУ/КТРУ xml.zip` (81 465 исходных строк минус 4 конфликтующие). 60 087 строк имеют статус `ACTIVE`, 21 374 — `TERMINATED`. `actual` означает последние версии, **не только действующие позиции**; 101 часть `not-actual` с историей не включена. XML сформированы 03.10.2026; преобразование выполнено 09.10.2026. Формат и пространства имён соответствуют ЕИС, но происхождение переданного ZIP независимо не проверялось.
Одна строка — одна исходная XML-позиция. Основные колонки: `code`, `version`, `version_code`, `name`, `status`, даты, `description`, `is_template`, `no_new_features`, `no_new_features_reason`; вложенные `okpd2`, `units`, `parent`, `cancellation`, `nsi`, `rubricators`, `characteristics`, `attachments`, `print_form`. `characteristics[].values[]` содержит исходный код значения, текст, `unit`, `format`, `concrete_values` и `ranges` с `min`, `max`, `min_operator`, `max_operator`. Это настоящие Parquet-списки и структуры, не строки с JSON.

Текст не обрезается; границы диапазонов и конкретные числа хранятся строками без потери точности, датировки — исходными ISO-строками с часовым поясом. Коды ОКЕИ сохраняют ведущие нули. Отсутствующее поле — `null`, присутствующий пустой текст — `""`, пустой список — `[]`. `type`, `kind`, `choice_type` сохраняются как исходные коды, без предположений об их семантике. `no_new_features=true` — запрет дополнительных характеристик; `null` означает отсутствие исходного признака.

**Конфликтующие пары исключены целиком:** коды `32.50.13.110-03169` и `32.50.13.110-03170`, версия 2, имели по две записи с разными названиями. Все четыре строки удалены из Parquet. Конвертер сохраняет их происхождение и названия в локальном отчёте проверки, который не публикуется. Конвертер автоматически исключает все строки любой конфликтующей пары `code + version`, не выбирая произвольно одну. Точные дубли без различий сохраняются. Идентичность исходной строки: `source_zip + source_xml + source_row` (нумерация с 1, без перенумерации после исключений).

Преимущества относительно старого JSON: исходные верхние и нижние границы, единицы и признаки характеристик, описания, причины/даты исключения, стандарты и классификаторы; колоночное чтение без загрузки всех аннотаций зеркала. Есть четыре кода, отсутствующие в JSON; пять JSON-кодов, которые XML содержит только в истории, намеренно не входят в этот actual-экспорт. Аннотации зеркала не подмешаны в исходные XML-данные.

Преобразование и полная проверка:

```bash
uv run --with pyarrow python scripts/convert_ktru_xml.py
uv run --with pyarrow python -m unittest discover -s scripts -p 'test_convert_ktru_xml.py'
```

Чтение отдельных колонок и вложенных характеристик:

```python
import pyarrow.parquet as pq

catalog = pq.read_table("data/ktru-actual.parquet", columns=["code", "name", "status", "characteristics"])
active = pq.read_table("data/ktru-actual.parquet", columns=["code", "name"], filters=[("status", "=", "ACTIVE")])
```

### КТРУ и ОКПД2: стороннее зеркало «Мои закупки»

- **`okpd2-moy-zakupki.parquet` — предпочтительный справочник ОКПД2 для КТРУ:** **22 246** записей из [API ОКПД2 moy-zakupki.ru](https://moy-zakupki.ru/api/app/okpd/list), `ordering=code`, `per_page=50`. Выгружены все страницы на момент сбора.

Для соединения с `ktru-actual.parquet` используйте `okpd2.code`, а не локальные ID или префикс КТРУ. Все 2 911 используемых кодов найдены в этом справочнике. Не отбрасывайте `is_actual=false`: такие коды используются в том числе позициями КТРУ со статусом `ACTIVE`.

**Это стороннее зеркало, не официальный снимок ЕИС.** Актуальность, полнота по России и происхождение добавленных зеркалом аннотаций независимо не подтверждались.

Коды и названия единиц измерения уже содержатся в записях КТРУ и СТЕ; отдельный справочник ОКЕИ в репозиторий не включён.

## Скрипты

В `../scripts/` сохранены загрузчики списков и карточек, возобновление/цепочки загрузок, прокси-мост, построение и проверка поискового датасета, а также `package_data.py` для gzip-упаковки локальных JSON. Нужен Python 3.12+; внешние зависимости — `requests`, `PySocks`, `pyarrow` (для Parquet-конвертеров).

```bash
uv run python scripts/package_data.py
```

Упаковщик работает с уже имеющимися локальными выгрузками и не скачивает недостающие каталоги.

Для сетевых загрузчиков необходимы собственные учётные данные в локальном `secrets/`: `zakupki-token`, `zakupki-proxy`, `deepseek-api-key` — в зависимости от скрипта. Секреты в репозиторий не включены. Прокси-скрипты используют адрес сервера и настройки, наблюдавшиеся при сборе; перед новым запуском необходимо проверить их актуальность.

## Ограничения

- Снимки отражают разные моменты выгрузки, не единую транзакцию всех внешних источников.
- Продолжающаяся локальная загрузка не обновляет уже опубликованный коммит.
- Публичная доступность API не означает автоматически разрешение на произвольное дальнейшее распространение данных; применимые условия источников следует проверить отдельно.
- SQLite-чекпойнты, исходные ZIP/JSON, браузерные дампы, веб-приложение и секреты намеренно не опубликованы. Parquet-каталоги публикуются через Git LFS.
