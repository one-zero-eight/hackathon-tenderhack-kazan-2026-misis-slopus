# Данные закупочных каталогов

Снимки собраны 6–9 октября 2026 года. Данные в репозитории хранятся **в gzip и Parquet**, через Git LFS; приложение из `search-web/`, секреты и рабочие SQLite-базы не включены. Предпочтительный источник КТРУ — `ktru-actual.parquet`; прежний `deprecated/ktru.json.gz` deprecated.

## Получение

Установите Git LFS перед клонированием:

```bash
git lfs install
git clone https://github.com/dantetemplar/zakupki-reverse.git
cd zakupki-reverse
git lfs pull
```

`*.json.gz` — JSON-массивы или JSON-объекты; `*.jsonl.gz` — один JSON-объект на строку; `*.parquet` — колоночные данные с внутренним сжатием, без дополнительного gzip. Служебные `*.meta.json` и `*.meta.json.gz` остаются только локально и не публикуются. `publish-manifest.json.gz` содержит размеры, SHA-256 файлов и количество записей для массивов/JSONL/Parquet. Контрольные суммы относятся к конкретному опубликованному снимку; добавленные локальные экспорты не появляются в старом манифесте автоматически.

Deprecated-наборы находятся в `data/deprecated/`; рекомендуемые замены остаются в `data/` и указаны ниже. Сравнения, пробные выборки, отдельные тестовые ответы и промежуточные прогоны находятся в `data/tmp/`; они не являются основными каталогами или финальными оценочными сплитами.

## Каталоги и источники

### СТЕ: Портал поставщиков Москвы

Источник: [zakupki.mos.ru](https://zakupki.mos.ru/).

- `ste.jsonl.gz`: **300 000** записей списка стандартных товарных единиц, упорядоченных по `id`. Первоначальная выборка получена через [публичный Search API](https://api.zakupki.mos.ru/api/v2/Sku/public/Search), затем расширена через [QueryIndex](https://zakupki.mos.ru/newapi/api/Sku/QueryIndex). Для расширения использованы состояния `entityState=2`, `skuStateId=61000002`; полный фильтр задан в скрипте `extend_ste_list_qi.py`. Это ограниченная выборка, не полный каталог и не случайная статистическая выборка.
- `ste-details.jsonl.gz`: **133 936** записей в опубликованном снимке подробных карточек из [GetSku](https://zakupki.mos.ru/classifier/api/Sku/GetSku). Сбор продолжался во время подготовки репозитория; точное количество карточек указано в `publish-manifest.json.gz`. Карточки содержат характеристики, описание, классификаторы и другие доступные поля. Записи с `_fetchError` отражают отказ доступа, а не полноценную карточку. Локальное состояние возобновляемой загрузки может отставать от файла и не является гарантией полноты.
- `tmp/ste.json.gz`, `tmp/ste-sample.json.gz`, `tmp/ste-sample-details.json.gz`, `tmp/ste-by-id-1159324.json.gz`: ранние выборки и отдельные ответы для исследования структуры; не дополнительные непересекающиеся наборы. Их нельзя суммировать с основной выгрузкой. Локальные браузерные дампы `ste-anonymous-*` и SQLite малого прогона также находятся в `tmp/`, но не публикуются.
- `ste-categories.json.gz`: **14 743** записи дерева категорий СТЕ из Портала поставщиков.
- `pp-kpgz.json.gz`: **15 075** записей классификатора продукции/КПГЗ в представлении Портала поставщиков, с иерархией и связями с ОКПД2.
- **`deprecated/okpd2.json.gz` — deprecated, предпочтителен `okpd2-moy-zakupki.json.gz`:** **21 686** записей ОКПД2 из справочников Портала поставщиков, включая корневую запись без кода; собственно непустых кодов — 21 685. Не содержит 29 кодов, используемых 3 865 позициями `ktru-actual.parquet`. Сохранён как архивный снимок Портала поставщиков; текущий поиск его не использует. ID разных источников не взаимозаменяемы.

Для последних трёх справочников сохранены полученные данные, но отдельный полный журнал HTTP-запросов не сохранился. Не следует считать идентификаторы одинаковыми между разными системами.

### КПГЗ и СПГЗ: ЕАИСТ Москвы

- **`deprecated/kpgz.json.gz` — deprecated, для работы с СТЕ предпочтителен `pp-kpgz.json.gz`:** **15 037** записей КПГЗ. Источник: [экспорт КПГЗ ЕАИСТ](https://eaist.mos.ru/module/nsiexportservice/api/v1/dicts/kpgz). Сохранён для сопоставления с СПГЗ ЕАИСТ; локальные ID не взаимозаменяемы с ID Портала поставщиков.
- `spgz.json.gz`: **83 485** записей СПГЗ, включая связи и характеристики. Источник: [экспорт СПГЗ ЕАИСТ](https://eaist.mos.ru/module/nsiexportservice/api/v1/dicts/spgz).

Это представление ЕАИСТ, отдельное от `pp-kpgz.json.gz`; совпадение кодов не означает совпадение локальных ID.

### КТРУ: предпочтительный XML → Parquet

- **`ktru-actual.parquet` — основной источник КТРУ:** **20,4 МБ** (Zstandard), **81 461 строка / уникальный код**, **330 542 характеристики**, **1 067 566 значений**, из 82 XML-частей `actual` архива `КТРУ/КТРУ xml.zip` (81 465 исходных строк минус 4 конфликтующие). 60 087 строк имеют статус `ACTIVE`, 21 374 — `TERMINATED`. `actual` означает последние версии, **не только действующие позиции**; 101 часть `not-actual` с историей не включена. XML сформированы 03.10.2026; преобразование выполнено 09.10.2026. Формат и пространства имён соответствуют ЕИС, но происхождение переданного ZIP независимо не проверялось.
Одна строка — одна исходная XML-позиция. Основные колонки: `code`, `version`, `version_code`, `name`, `status`, даты, `description`, `is_template`, `no_new_features`, `no_new_features_reason`; вложенные `okpd2`, `units`, `parent`, `cancellation`, `nsi`, `rubricators`, `characteristics`, `attachments`, `print_form`. `characteristics[].values[]` содержит исходный код значения, текст, `unit`, `format`, `concrete_values` и `ranges` с `min`, `max`, `min_operator`, `max_operator`. Это настоящие Parquet-списки и структуры, не строки с JSON.

Текст не обрезается; границы диапазонов и конкретные числа хранятся строками без потери точности, датировки — исходными ISO-строками с часовым поясом. Коды ОКЕИ сохраняют ведущие нули. Отсутствующее поле — `null`, присутствующий пустой текст — `""`, пустой список — `[]`. `type`, `kind`, `choice_type` сохраняются как исходные коды, без предположений об их семантике. `no_new_features=true` — запрет дополнительных характеристик; `null` означает отсутствие исходного признака.

**Конфликтующие пары исключены целиком:** коды `32.50.13.110-03169` и `32.50.13.110-03170`, версия 2, имели по две записи с разными названиями. Все четыре строки удалены из Parquet. Конвертер сохраняет их происхождение и названия в локальном отчёте проверки, который не публикуется. Конвертер автоматически исключает все строки любой конфликтующей пары `code + version`, не выбирая произвольно одну. Точные дубли без различий сохраняются. Идентичность исходной строки: `source_zip + source_xml + source_row` (нумерация с 1, без перенумерации после исключений).

Преимущества относительно старого JSON: исходные верхние и нижние границы, единицы и признаки характеристик, описания, причины/даты исключения, стандарты и классификаторы; колоночное чтение без загрузки всех аннотаций зеркала. Есть четыре кода, отсутствующие в JSON; пять JSON-кодов, которые XML содержит только в истории, намеренно не входят в этот actual-экспорт. Аннотации зеркала не подмешаны в исходные XML-данные.

Преобразование и полная проверка:

```bash
uv run --with pyarrow python scripts/convert_ktru_xml.py
uv run --with pyarrow python -m unittest discover -s scripts -p 'test_convert_ktru_xml.py'
```

Чтение отдельных колонок и вложенных характеристик:

```python
import pyarrow.parquet as pq

catalog = pq.read_table("data/ktru-actual.parquet", columns=["code", "name", "status", "characteristics"])
active = pq.read_table("data/ktru-actual.parquet", columns=["code", "name"], filters=[("status", "=", "ACTIVE")])
```

### КТРУ и ОКПД2: стороннее зеркало «Мои закупки»

- **`deprecated/ktru.json.gz` — deprecated, предпочтителен `ktru-actual.parquet`:** **81 464** записи из [API КТРУ moy-zakupki.ru](https://moy-zakupki.ru/api/app/ktru/list), параметры `is_last_version=true`, `ordering=code`, `per_page=50`. Сохранены исходные поля, в том числе `characteristics_jsonb` и аннотации зеркала.
- **`okpd2-moy-zakupki.json.gz` — предпочтительный справочник ОКПД2 для КТРУ:** **22 246** записей из [API ОКПД2 moy-zakupki.ru](https://moy-zakupki.ru/api/app/okpd/list), `ordering=code`, `per_page=50`. Выгружены все страницы на момент сбора.
- `tmp/ktru-okpd2-moy-zakupki.json.gz`: **81 464** вычисленных связи КТРУ → ОКПД2 по внутренним ID этого зеркала. Все ссылки разрешены; у 4 854 записей префикс кода КТРУ отличается от связанного кода ОКПД2. Это наблюдение о данных, не автоматическое исправление.
- `tmp/okpd2-moy-zakupki-comparison.json.gz`: сравнение двух представлений ОКПД2: 21 685 общих кодов, 561 дополнительный код зеркала, 93 различия наименований; также расхождения префиксов КТРУ.

Для соединения с `ktru-actual.parquet` используйте `okpd2.code`, а не локальные ID или префикс КТРУ. Все 2 911 используемых кодов найдены в расширенном справочнике. Не отбрасывайте `is_actual=false`: такие коды используются в том числе позициями КТРУ со статусом `ACTIVE`.

**Это стороннее зеркало, не официальный снимок ЕИС.** Актуальность, полнота по России и происхождение добавленных зеркалом аннотаций независимо не подтверждались.

### ОКЕИ: открытые данные Росстата — deprecated

- **`deprecated/okei.csv.gz` — deprecated:** самостоятельный справочник не требуется для чтения КТРУ и СТЕ: коды и названия единиц уже содержатся в исходных записях. Сохранён для справочных проверок. **543 кода и 20 строк заголовков** Общероссийского классификатора единиц измерения, версия от 03.12.2024. Источник: [набор открытых данных Росстата](https://rosstat.gov.ru/opendata/7708234640-okei), файл `data-20241203T1712-structure-20180402T1704.csv` без изменений. CSV без заголовка, разделитель `;`, UTF-8; поля `Razdel;Podrazdel;Code;Name`. Строки с пустым кодом — заголовки разделов и подразделов. В наименованиях `^` обозначает перенос строки, внутри кавычек может встречаться `;`.

Сверка с `ktru-actual.parquet`: найдены все 49 кодов единиц позиций и 102 из 103 кодов единиц характеристик. Исключение — `D111` («Действующее вещество: Миллилитр»), 30 значений в 30 позициях; код подтверждён в исходном XML и сохраняется без замены на `111`. Различия названий — оформление, сокращения и опечатка «Киллограмм» для кода `316` в CSV Росстата. Для соединения используйте код, сохраняя ведущие нули и исходные названия.

Набор содержит только коды и наименования, без условных обозначений («шт», «кг») и буквенных кодов.

## Поисковый датасет СТЕ

В `ste-search-dataset/` опубликованы gzip-версии финального JSONL:

- `train.jsonl.gz` — 800 запросов;
- `validation.jsonl.gz` — 100;
- `test.jsonl.gz` — 100;
- `all.jsonl.gz` — объединение всех 1 000, не отдельная выборка.

Исторический промежуточный экспорт `tmp/ste-search-dataset/partial.jsonl.gz` содержит **657** уникальных запросов. Не использовать вместо финальных сплитов. Его локальные статус и пробные ответы `probe-*` также перенесены в `tmp/ste-search-dataset/`. Финальные `train`, `validation`, `test` и `all`, а также рабочие данные и свидетельства их построения остаются в `ste-search-dataset/`.

Запросы синтетические, созданы и размечены моделью **`deepseek-flash`** через [DeepSeek API](https://api.deepseek.com/). 50 товарных семейств, 10 типов запросов, по 100 запросов каждого типа: опечатки, сокращения, профессиональный сленг, перестановка слов, синонимы, неполные названия, альтернативные единицы, неоднозначность, естественный язык и смешанный шум.

Каждая финальная запись содержит запрос, релевантную СТЕ, 3–5 сложных отрицательных примеров, кандидатов, свидетельства характеристик, оценки и ссылки на локальные HTTP-архивы, которые не включены в репозиторий. Рубрика: `0` — явное критическое несоответствие/нерелевантность; `1` — частичное соответствие или неизвестный критический параметр; `2` — соответствие всем явно заданным требованиям.

Кандидаты взяты из живого поиска Портала поставщиков. Для точного запроса сохранена полная **первая страница из 20 результатов**, а не все совпадения. Кандидаты, добытые поиском по семейству и отсутствующие в точной выдаче, явно помечены `family_search`.

Автоматические проверки подтверждают баланс сплитов, уникальность нормализованных запросов, отсутствие общих релевантных/сложных отрицательных STE-ID между сплитами и обнаруженных лексических близких дублей. Семантические/продуктовые семейства не разделяются между сплитами. **Это не человеческая разметка и не доказательство отсутствия любого семантического leakage.**

## Скрипты

В `../scripts/` сохранены загрузчики списков и карточек, возобновление/цепочки загрузок, прокси-мост, построение и проверка поискового датасета, а также `package_data.py` для gzip-упаковки публикации. Нужен Python 3.12+; внешние зависимости — `requests`, `PySocks`, `ijson` (для упаковщика), `pyarrow` (для Parquet-конвертера и упаковщика).

```bash
uv run --with requests --with PySocks --with ijson --with pyarrow python scripts/package_data.py
```

Упаковщик работает с уже имеющимися локальными выгрузками и не скачивает недостающие каталоги. Создание нового снимка переупаковывает данные; его контрольные суммы могут отличаться от опубликованного коммита.

Для сетевых загрузчиков необходимы собственные учётные данные в локальном `secrets/`: `zakupki-token`, `zakupki-proxy`, `deepseek-api-key` — в зависимости от скрипта. Секреты в репозиторий не включены. Прокси-скрипты используют адрес сервера и настройки, наблюдавшиеся при сборе; перед новым запуском необходимо проверить их актуальность.

## Ограничения

- Снимки отражают разные моменты выгрузки, не единую транзакцию всех внешних источников.
- Продолжающаяся локальная загрузка не обновляет уже опубликованный коммит.
- Публичная доступность API не означает автоматически разрешение на произвольное дальнейшее распространение данных; применимые условия источников следует проверить отдельно.
- SQLite-чекпойнты, исходные ZIP, браузерные диагностические дампы/скриншоты, веб-приложение и секреты намеренно не опубликованы. `ktru-actual.parquet` включён в правила публикации через Git LFS.
