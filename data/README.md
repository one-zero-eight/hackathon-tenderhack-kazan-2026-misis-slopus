# Данные закупочных каталогов

Снимки собраны 6–8 октября 2026 года. Данные в репозитории хранятся **только в gzip-виде**, через Git LFS; приложение из `search-web/`, секреты и рабочие SQLite-базы не включены.

## Получение

Установите Git LFS перед клонированием:

```bash
git lfs install
git clone https://github.com/dantetemplar/zakupki-reverse.git
cd zakupki-reverse
git lfs pull
```

`*.json.gz` — JSON-массивы или JSON-объекты; `*.jsonl.gz` — один JSON-объект на строку. Файлы `*.meta.json.gz` содержат параметры источника и состояние выгрузки. `publish-manifest.json.gz` содержит размеры, SHA-256 сжатых файлов и количество записей для массивов/JSONL. Контрольные суммы относятся к конкретному коммиту, а не к продолжающейся локальной загрузке.

## Каталоги и источники

### СТЕ: Портал поставщиков Москвы

Источник: [zakupki.mos.ru](https://zakupki.mos.ru/).

- `ste.jsonl.gz`: **300 000** записей списка стандартных товарных единиц, упорядоченных по `id`. Первоначальная выборка получена через [публичный Search API](https://api.zakupki.mos.ru/api/v2/Sku/public/Search), затем расширена через [QueryIndex](https://zakupki.mos.ru/newapi/api/Sku/QueryIndex). Для расширения использованы состояния `entityState=2`, `skuStateId=61000002`; полный фильтр сохранён в метаданных. Это ограниченная выборка, не полный каталог и не случайная статистическая выборка.
- `ste-details.jsonl.gz`: **133 936** записей в опубликованном снимке подробных карточек из [GetSku](https://zakupki.mos.ru/classifier/api/Sku/GetSku). Сбор продолжался во время подготовки репозитория; точное количество карточек указано в `publish-manifest.json.gz`. Карточки содержат характеристики, описание, классификаторы и другие доступные поля. Записи с `_fetchError` отражают отказ доступа, а не полноценную карточку. Количество и `targetCount` в старых метаданных могут отставать от файла: это история возобновляемой загрузки, а не гарантия полноты.
- `ste.json.gz`, `ste-sample.json.gz`, `ste-sample-details.json.gz`, `ste-by-id-1159324.json.gz`: ранние выборки и отдельные ответы для исследования структуры; не дополнительные непересекающиеся наборы. Их нельзя суммировать с основной выгрузкой.
- `ste-categories.json.gz`: **14 743** записи дерева категорий СТЕ из Портала поставщиков.
- `pp-kpgz.json.gz`: **15 075** записей классификатора продукции/КПГЗ в представлении Портала поставщиков, с иерархией и связями с ОКПД2.
- `okpd2.json.gz`: **21 686** записей ОКПД2 из справочников Портала поставщиков, включая корневую запись без кода; собственно непустых кодов — 21 685.

Для последних трёх справочников сохранены полученные данные, но отдельный полный журнал HTTP-запросов не сохранился. Не следует считать идентификаторы одинаковыми между разными системами.

### КПГЗ и СПГЗ: ЕАИСТ Москвы

- `kpgz.json.gz`: **15 037** записей КПГЗ. Источник: [экспорт КПГЗ ЕАИСТ](https://eaist.mos.ru/module/nsiexportservice/api/v1/dicts/kpgz).
- `spgz.json.gz`: **83 485** записей СПГЗ, включая связи и характеристики. Источник: [экспорт СПГЗ ЕАИСТ](https://eaist.mos.ru/module/nsiexportservice/api/v1/dicts/spgz).

Это представление ЕАИСТ, отдельное от `pp-kpgz.json.gz`; совпадение кодов не означает совпадение локальных ID.

### КТРУ и ОКПД2: стороннее зеркало «Мои закупки»

- `ktru.json.gz`: **81 464** записи из [API КТРУ moy-zakupki.ru](https://moy-zakupki.ru/api/app/ktru/list), параметры `is_last_version=true`, `ordering=code`, `per_page=50`. Сохранены исходные поля, в том числе `characteristics_jsonb` и аннотации зеркала.
- `okpd2-moy-zakupki.json.gz`: **22 246** записей из [API ОКПД2 moy-zakupki.ru](https://moy-zakupki.ru/api/app/okpd/list), `ordering=code`, `per_page=50`. Выгружены все страницы на момент сбора.
- `ktru-okpd2-moy-zakupki.json.gz`: **81 464** вычисленных связи КТРУ → ОКПД2 по внутренним ID этого зеркала. Все ссылки разрешены; у 4 854 записей префикс кода КТРУ отличается от связанного кода ОКПД2. Это наблюдение о данных, не автоматическое исправление.
- `okpd2-moy-zakupki-comparison.json.gz`: сравнение двух представлений ОКПД2: 21 685 общих кодов, 561 дополнительный код зеркала, 93 различия наименований; также расхождения префиксов КТРУ.

**Это стороннее зеркало, не официальный снимок ЕИС.** Актуальность, полнота по России и происхождение добавленных зеркалом аннотаций независимо не подтверждались.

### ОКЕИ: открытые данные Росстата

- `okei.csv.gz`: **562** строки Общероссийского классификатора единиц измерения, версия от 03.12.2024. Источник: [набор открытых данных Росстата](https://rosstat.gov.ru/opendata/7708234640-okei), файл `data-20241203T1712-structure-20180402T1704.csv` без изменений. CSV без заголовка, разделитель `;`, UTF-8; поля `Razdel;Podrazdel;Code;Name`. Строки с пустым кодом — заголовки разделов и подразделов. В наименованиях `^` обозначает перенос строки, внутри кавычек может встречаться `;`.

Набор содержит только коды и наименования, без условных обозначений («шт», «кг») и буквенных кодов.

## Поисковый датасет СТЕ

В `ste-search-dataset/` опубликованы gzip-версии финального JSONL:

- `train.jsonl.gz` — 800 запросов;
- `validation.jsonl.gz` — 100;
- `test.jsonl.gz` — 100;
- `all.jsonl.gz` — объединение всех 1 000, не отдельная выборка;
- `partial.jsonl.gz` — исторический промежуточный экспорт, **657** уникальных запросов. Не использовать вместо финальных сплитов.

Запросы синтетические, созданы и размечены моделью **`deepseek-flash`** через [DeepSeek API](https://api.deepseek.com/). 50 товарных семейств, 10 типов запросов, по 100 запросов каждого типа: опечатки, сокращения, профессиональный сленг, перестановка слов, синонимы, неполные названия, альтернативные единицы, неоднозначность, естественный язык и смешанный шум.

Каждая финальная запись содержит запрос, релевантную СТЕ, 3–5 сложных отрицательных примеров, кандидатов, свидетельства характеристик, оценки и ссылки на локальные HTTP-архивы, которые не включены в репозиторий. Рубрика: `0` — явное критическое несоответствие/нерелевантность; `1` — частичное соответствие или неизвестный критический параметр; `2` — соответствие всем явно заданным требованиям.

Кандидаты взяты из живого поиска Портала поставщиков. Для точного запроса сохранена полная **первая страница из 20 результатов**, а не все совпадения. Кандидаты, добытые поиском по семейству и отсутствующие в точной выдаче, явно помечены `family_search`.

Автоматические проверки подтверждают баланс сплитов, уникальность нормализованных запросов, отсутствие общих релевантных/сложных отрицательных STE-ID между сплитами и обнаруженных лексических близких дублей. Семантические/продуктовые семейства не разделяются между сплитами. **Это не человеческая разметка и не доказательство отсутствия любого семантического leakage.**

## Скрипты

В `../scripts/` сохранены загрузчики списков и карточек, возобновление/цепочки загрузок, прокси-мост, построение и проверка поискового датасета, а также `package_data.py` для gzip-упаковки публикации. Нужен Python 3.12+; внешние зависимости — `requests`, `PySocks`, `ijson` (последняя только для упаковщика).

```bash
uv run --with requests --with PySocks --with ijson python scripts/package_data.py
```

Упаковщик работает с уже имеющимися локальными выгрузками и не скачивает недостающие каталоги. Создание нового снимка переупаковывает данные; его контрольные суммы могут отличаться от опубликованного коммита.

Для сетевых загрузчиков необходимы собственные учётные данные в локальном `secrets/`: `zakupki-token`, `zakupki-proxy`, `deepseek-api-key` — в зависимости от скрипта. Секреты в репозиторий не включены. Прокси-скрипты используют адрес сервера и настройки, наблюдавшиеся при сборе; перед новым запуском необходимо проверить их актуальность.

## Ограничения

- Снимки отражают разные моменты выгрузки, не единую транзакцию всех внешних источников.
- Продолжающаяся локальная загрузка не обновляет уже опубликованный коммит.
- Публичная доступность API не означает автоматически разрешение на произвольное дальнейшее распространение данных; применимые условия источников следует проверить отдельно.
- SQLite-чекпойнты, ZIP-дубликаты, браузерные диагностические дампы/скриншоты, Parquet, веб-приложение и секреты намеренно не опубликованы.
